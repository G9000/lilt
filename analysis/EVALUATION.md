# Lilt analysis helper: evaluation (synthetic fixtures only)

_Generated by `scripts/evaluate.py`; do not edit by hand. Re-run after any change to the algorithm, parameters, Praat/Parselmouth version or decoding._

## Status: descriptive only

**Natural-speech validation has NOT been done.** No natural-speech recordings with independently checked reference pitch contours were available. Every result below comes from synthetic signals (tones, noise, glides) or synthetic text-to-speech. These results show that the software behaves as specified on known signals; they do not show that pitch measurements are accurate on real voices, microphones or rooms. All measures are therefore `use_status: descriptive_only` and must not drive corrective feedback or progression.

## Versions and algorithm actually used

- Parselmouth 0.4.7, bundled Praat 6.1.38 (2 January 2021)
- PyAV 19.0.2 (bundled FFmpeg libavformat 63.1.102), NumPy 2.5.4, Python 3.12.10 on Darwin arm64
- Pitch algorithm used: **`ac`** (`To Pitch (ac)`)
- Selection: 'To Pitch (filtered autocorrelation)' not usable in bundled Praat 6.1.38 (PraatError: Command "To Pitch (filtered autocorrelation)" not available for given objects.); using raw autocorrelation. Self-check: 220 Hz calibration tone -> median 220.000 Hz, ceiling 700 Hz
- Parameters (fixed for every take, no gender-based range): `{"time_step": 0.01, "pitch_floor": 60.0, "max_number_of_candidates": 15, "very_accurate": false, "silence_threshold": 0.03, "voicing_threshold": 0.45, "octave_cost": 0.01, "octave_jump_cost": 0.35, "voiced_unvoiced_cost": 0.14, "pitch_ceiling": 700.0}`
- Octave-jump ratio 1.8 (and 1/1.8); clip threshold |x| >= 0.999; low signal < -50.0 dBFS RMS; minimum voiced material 0.5 s

Filtered autocorrelation (Praat >= 6.4, which Praat recommends for intonation) is **not** available: the newest Parselmouth on PyPI bundles an older Praat. The code probes for it on every start and will switch automatically (after a calibration self-check) if a newer Parselmouth provides it; that path is untested here. Switching algorithms changes results, so historical takes must then be reanalysed for matched comparisons.

## Known failures found by this evaluation

- **Short octave section tracked at the subharmonic.** In `octave_jump_short` (0.3 s at 400 Hz inside 200 Hz) raw AC with Praat's default path costs reports ~200 Hz throughout: gross error rate 13.4 %, 0 suspected jumps, no flag. A perfectly periodic synthetic tone is equally periodic at half its frequency, and the octave-jump cost outweighs the small octave cost over 30 frames. With 0.8 s at 400 Hz (`octave_jump`) both jumps are tracked and reported. So *the absence of suspected octave jumps does not prove the absence of octave errors.* This fixture is reported, not asserted.
- The octave-jump detector flags any abrupt ratio > 1.8 between adjacent voiced frames. It cannot tell a tracking error from a genuine pitch break (both are in `octave_jump`); jumps are reported, never corrected.
- **AAC/MP4 timing offset.** Voiced segments in `mixed_voiced_unvoiced.mp4` are [[0.5147, 1.0247], [1.5147, 2.2247]] vs truth [[0.5, 1.0], [1.5, 2.2]]: shifted later by up to ~25 ms, and the decoded file is slightly longer than the source. This is consistent with AAC encoder priming samples not being trimmed for this fragmented MP4 (cause not verified). Timestamps from MP4 input should be treated as accurate to about +/- 30 ms. Real Safari recordings were not tested.
- Truncation is detected from decoder evidence (demuxer 'File ended prematurely', corrupt packets, a decode error after valid frames, or a declared duration longer than what decoded). A file cut exactly on a block boundary with no declared duration (typical of MediaRecorder WebM) is indistinguishable from a complete short recording.

## Synthetic speech (macOS `say`) — algorithm cross-check, not ground truth

These are text-to-speech outputs: lawful synthetic speech, **not natural speech**. There is no reference contour. Because filtered autocorrelation is unavailable, the planned filtered-AC vs raw-AC comparison could not be run; instead the pipeline's raw AC contour is compared with Praat's cross-correlation method (`To Pitch (cc)`, same 60–700 Hz range and 10 ms step, Praat defaults otherwise) on the identical derived samples. Agreement between two algorithms from the same toolkit is a consistency check only; it is not validation.

## What is not evaluated

- Natural speech with independent reference contours (the evaluation asset that is missing). Until it exists, measurements stay descriptive only.
- Real browser recordings (Chrome/Firefox WebM, Safari MP4) from real microphones; only PyAV encodes were decoded.
- Noisy, reverberant or low-SNR voiced speech; breathy, creaky or very high voices; voices near the 60 or 700 Hz limits.
- Any link between these measures and perceived femininity, resonance or lightness. None is claimed.
